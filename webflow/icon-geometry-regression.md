# Burger X geometry candidate

The released `v0.2.3` CSS uses a fixed 7px shift (or half that for two bars). That matches only the original 2px bars and 5px gap. The maintained source now measures the rendered bar height plus the icon's row gap and sets `--mwp-nav-icon-auto-shift` on the root. The existing transform transition remains intact, so the bars still move and rotate smoothly. An explicit `--mwp-nav-icon-shift` remains a manual override, and its 7px fallback remains available without JavaScript.

On 2026-10-02 a localhost browser fixture loaded the maintained CSS and JavaScript, used native summary/icon/line markup and exercised three and two visible lines. At 2px bars with a 5px gap the measured shift was 7px; at 3px bars with a 7px gap it was 10px. After the opening transition settled, the first and final line centres matched exactly in all four cases: 8px and 11.5px for three lines, 4.5px and 6.5px for two lines, measured from the icon top. The browser's rendered sample showed symmetric Xs. The automated suite additionally verifies recalculation when the gap changes, and all 36 tests pass.

This is a source candidate, not a released Webflow component change. Before release, visually inspect the native two-line and three-line icons on the source component and linked consumer at device-pixel ratios above 1, with odd and even bar thicknesses. Verify that Webflow's native icon classes expose their computed gap and bar height in Preview. Then run the full release matrix against exact versioned assets.

On the clean linked `SmashBurger CDN` instance in SB Test Five, Designer Preview exposed a computed `5px` row gap and `2px` height on each native line element. Switching the `Icon lines` instance property to `2` hid the middle line in Preview; restoring `3` showed all three again. At Chrome's emulated iPhone SE pixel ratio of `2` and iPhone 16 pixel ratio of `3`, both the open three-line and two-line icons rendered as centred Xs. The three-line bars translated by `7px` and `-7px`; the two-line bars translated by `3.5px` and `-3.5px`, with the middle line hidden. The menu opened in all four density/icon combinations. Chrome device emulation and DevTools were turned off, and the instance property was restored to `3`. The page remains unpublished.

This verifies the **released default geometry** at 2x and 3x on one linked consumer. It does not verify the maintained auto-shift candidate, odd bar thickness or overridden gap. Those checks remain before release.

On 2026-10-03, a temporary Code Embed on the same unpublished SB Test Five page loaded the **exact maintained CSS and JavaScript source**, plus two isolated native-HTML fixture roots. Both used a `7px` icon gap and `3px` bars, with no manual shift token. The candidate initialized both roots in Designer Preview and wrote `--mwp-nav-icon-auto-shift: 10px`. The three-line open X translated by `10px` and `-10px`; all three bar centres converged at `11.5px` within the icon. The two-line open X hid the middle bar, translated by `5px` and `-5px`, and both visible centres converged at `6.5px`. Both opened with `aria-expanded="true"`, produced no horizontal overflow at the 240px Preview width, and the two-line menu closed on Escape with focus returned to its trigger. The temporary Embed was removed afterward, restoring the clean linked-import page.

This confirms the full source candidate in Webflow Preview with odd bar thickness and overridden spacing. The fixture markup came from an Embed rather than editable Webflow elements, and it was not published. Native source-component, linked-consumer and versioned-distribution checks remain.

## Native Webflow high-DPI measurement (2026-10-13)

On the same unpublished isolation fixture, the maintained CSS/JavaScript source was loaded into its temporary test Embed with native Webflow icon and line Divs. At Tablet width (820px), the 3px bars and overridden 7px gap produced a 10px auto shift. With the menu open, the three-line icon's three bar centres all measured 36px. The two-line configuration hid the middle bar and its two visible bar centres both measured 36px. The panel's open state remained `aria-expanded="true"`, `aria-hidden="false"`, and not inert; document overflow was zero.

The same measurements were repeated in Chrome device emulation at DPR 2× (iPhone SE) and DPR 3× (iPhone 16). Both two-line and three-line modes retained the same 36px centre alignment, 3px computed bar height, 7px row gap, 10px JS-measured auto shift and zero overflow. One 3× three-line Preview screenshot showed the expected X. This confirms the maintained geometry candidate on editable native Webflow elements for an odd 3px thickness at the selected project gap.

For the even 4px thickness, the first full-source attempt hit Webflow's repeated Embed execution behavior: Designer re-rendering evaluated the temporary inline script again, producing `Identifier 'ROOT_SELECTOR' has already been declared`. To avoid rerunning that script, a second pass used the maintained CSS only and set the expected `--mwp-nav-icon-auto-shift: 11px` for 4px bars plus the 7px gap. At both DPR 2× and 3×, both icon modes converged their visible line centres at 36px; the two-line mode hid the middle bar and overflow remained zero. A 3× screenshot showed the expected X. This verifies even-thickness rendering on native elements at high DPR, but does not verify the JS recalculating 11px for a 4px bar.

The fixture's original root attributes were read back without the temporary `data-icon-lines` marker. Its pinned 1,314-character v0.2.6 loader was restored and read back byte-for-byte. Chrome device emulation and DevTools were turned off/closed; Preview was reloaded at Desktop. Nothing was published. Candidate linked-consumer and exact versioned-distribution checks remain.
